# 保费补退定义

每份保单有且仅有一条issue基线。change按effective、责任、version选版；同生效日同版本矛盾拒绝。cancel必须引用同保单的change，取消整份变更，不按录入顺序覆盖。区间为[start,end)。年度保费按所在自然年365或366日拆分，跨年强制切段。先求每段精确保费，再最大余额法分配到分，使段合计等于保单总额。paid为已收金额，总应收减已收为补退额，正数补缴、负数退费。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

## 多缴款结算

保费更正后，实收高于更正后应收的部分为多缴款（overpayment）。多缴款此前可能已转成缴清增额。财务要求尽快退现、核保要求总保障不缩水，二者冲突，按下列唯一规则裁决：

1. 保障底线 = 原保单原始年保费 × 保单期限折算年数 × `coverage_multiple`。期限折算年数按各区间 `days/year_days` 求和，整年保单为 1。
2. 更正后保障 = 更正后应收保费 × `coverage_multiple`。
3. 保障缺口 gap = max(保障底线 − 更正后保障, 0)。缺口只能由缴清增额补足：应留存保费 = ceil(gap / `paid_up_rate`)。
4. 留存保费 = min(多缴款, 应留存保费)；退现 = 多缴款 − 留存保费。多缴款不足以补足缺口时，全额留存、不得退现，并登记保障缺口违规。
5. 实收低于应收形成待收金额 receivable，与退费分列，不做抵销；`net_refund = refund − receivable` 仅供说明。

守恒：每份保单 `refund + retained_premium == overpayment`，故批次合计退费 + 留存 = 多缴款合计，`attribution.residual` 必为 0，`fully_attributed` 必为真。办结后每笔多缴款都有归属（退现或留存缴清增额），无悬空资金。`coverage.preserved` 为真表示所有发生退款的保单处置后保障不低于底线；为假时该批次不得结案下载（返回 COVERAGE），须先复核处置。

结算由输入与 `SETTLEMENT_RULE_VERSION` 完全决定，不累计历史，重跑同一更正得到同一结算，不新增退费或增额。结案后原始凭据可能被清理，结算快照内固化每笔实收的来源行、原始字段与源文件 sha256（`evidence`），争议时可追溯。结算单独持久化并以原子事务替换：写入前做守恒校验，内容相同不改写、不加版本，内容变化才递增 rev；替换失败回滚，旧版继续对外提供。复核界面、`/api/settlement/<run_id>` 与结案下载共用同一份已存结算。
